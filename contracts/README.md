# Shared contracts

Anything that two or more services must agree on lives in this folder.
Services implement these contracts; they never redefine them privately.

| Folder        | What                                             | Format                        | Checked in CI by                         |
|---------------|--------------------------------------------------|-------------------------------|------------------------------------------|
| `api/`        | REST APIs (browser-facing and service-to-service) | OpenAPI 3.1, one file per service | Redocly lint                          |
| `events/`     | AMQP event envelope, event payloads, RabbitMQ topology | JSON Schema 2020-12 + README | schema compile + example validation |
| `grpc/`       | Internal gRPC APIs used by the Sync Service      | Protobuf, managed by `buf`    | `buf lint`, `buf breaking` vs MR target  |
| `websocket/`  | Jam/Sync browser <-> server messages             | JSON Schema + README          | schema compile + example validation      |

The CI jobs live in the root `.gitlab-ci.yml` (`contracts:*`) and only run
when files in this folder change.

## Conventions for every contract

### IDs

| ID            | Format                         | Generated by                    |
|---------------|--------------------------------|---------------------------------|
| `song_id`     | UUID v4 string                 | Upload Service (on upload)      |
| `playlist_id` | UUID v4 string                 | Playlist Service                |
| `jam_id`      | UUID v4 string                 | Jam Service                     |
| `event_id`    | UUID v4 string                 | the event's producer            |
| `user_id`     | UUID v4 string                 | **proposal:** generated by the browser on first visit and kept in local storage, because no auth service is in scope. Team to confirm. |

### Field names and timestamps

- JSON field names are `snake_case`.
- Timestamps in REST bodies and AMQP events are ISO-8601 UTC strings,
  e.g. `2026-10-08T12:00:00.000Z`.
- WebSocket synchronisation messages use **integer epoch milliseconds**
  (`*_ms` fields), because clock-offset and `PLAY_AT(T)` arithmetic needs
  plain numbers.

### Song contract (owned by the Catalogue Service)

```text
song_id            UUID
title              string
artist             string
duration_ms        integer
audio_reference    string    S3 object key, e.g. "audio/<song_id>.mp3"
lyrics_status      PENDING | PROCESSING | READY | FAILED
waveform_status    PENDING | PROCESSING | READY | FAILED
processing_status  PROCESSING | PARTIAL | READY | FAILED
created_at         timestamp
updated_at         timestamp
```

`processing_status` is derived from the two stage statuses (plan.md §16):
`READY` when both are `READY`, `PARTIAL` when one is `READY` and the other
`FAILED`, `FAILED` when both failed, otherwise `PROCESSING`.

### REST basics

- Every service exposes `GET /health`, which returns `200 {"status":"ok"}`.
  Compose healthchecks, the gateway smoke test and ECS all use it.
- Errors use a single shape:
  `{"error": {"code": "SONG_NOT_FOUND", "message": "human readable"}}`.
- Services serve their routes **without** the `/api/<service>` prefix; the
  gateway strips it (see `infrastructure/gateway/nginx.conf`).

## Changing a contract

1. Change the contract in the same MR as the producer side, or before it.
2. Tag the owner of every service that produces or consumes the contract
   in the MR description, and get their approval before merging
   (plan.md §10 contract rule).
3. Prefer **additive** changes: new optional fields, new events, new RPCs.
4. A **breaking** change needs a new version: bump the event `version`, add
   a `v2` protobuf package, or add a new REST path. Keep the old version
   until every consumer has moved over. `buf breaking` fails MRs that break
   gRPC compatibility by accident.
